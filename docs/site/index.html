Building blocks

Everything you need to run work

⚙

Scheduling

Delayed jobs, recurring schedules, and flexible scheduling strategies for when work should run.

⚡

Execution Runtime

Manage work, workers, lifecycle, cancellation, concurrency, and the environment where workloads run.

⇄

Queues

Move work between producers and workers with control over concurrency, delivery, retries, and backpressure.

🛠

Workers

Processes that execute work concurrently, shut down gracefully, respond to cancellation, and report state.

🔄

Workflows

Compose multiple pieces of work into larger flows with dependencies, branching, retries, and state.

📣

Events

Components communicate changes and execution results without tightly coupling every part of the system.

Design principles

Simple, composable, observable

01

Go first

Built in Go. Standard library wherever it provides a good solution. Dependencies earn their place.

02

Concurrency is core

Cancellation, deadlines, worker lifecycle, backpressure, and graceful shutdown are first-class concerns.

03

Failure is normal

Workers fail. Networks fail. Tukma treats failure handling as part of execution, not an afterthought.

04

Earn the complexity

No Kafka, Kubernetes, or Temporal on day one. Complexity arrives when requirements justify it.
